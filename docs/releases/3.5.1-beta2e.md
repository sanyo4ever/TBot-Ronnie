# TBot 3.5.1-beta2e

An explicit `Not enough deuterium! (140026)` rejection from the pinned ogamed backend used to be treated as an uncertain launch because ogamed returned HTTP 500. This could leave an expedition slot unused and block later sends from that origin to the same destination for the lifetime of the process, even after refuelling.

The complete captured fuel-rejection envelope now permits a later worker cycle to try again. The original server reason remains in the log. There is no automatic replay of the failed POST. Timeouts, connection failures, unknown server errors, malformed JSON, incomplete envelopes and conflicting fields retain movement reconciliation and duplicate protection. Other message formats remain conservative.

All fixes from 3.5.1-beta2d, including primary/secondary expedition sharing and highscore navigation, are retained. The Go gitlink remains `5e921560dc524cd0d6caa614f6f8984ebaf135fc`.

Validation: 588 offline C# tests, including 27 new dispatch-boundary cases; independent review passed all 51 dispatch-boundary tests. Release-version policy and local migration tests passed. The release workflow runs the full Go suite/build and produces seven platform packages. Existing dependency advisories are unchanged. No live fleet sends were performed during verification.

Stop the old client normally before starting this version. Restarting clears any uncertain-dispatch block retained by the old process. Ensure the expedition origin has sufficient deuterium; this fix does not supply fuel.
