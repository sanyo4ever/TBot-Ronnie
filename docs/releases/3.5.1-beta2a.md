# TBot 3.5.1-beta2a

Our first maintenance revision on [Ronnie's v3.5.1-beta2](https://github.com/ronnie32/TBot/releases/tag/v3.5.1-beta2), published from the direct [TBot-Ronnie fork](https://github.com/sanyo4ever/TBot-Ronnie). The author's beta2 identity is preserved; this remains a prerelease. Base TBot commit: `521f43f3bb56aa01f847a6b56a89e46b774e0016`; Go release base: `e9f365f803e15f937916ef152462f231b8676512`. Each archive records its actual integrated source SHAs and exact Go gitlink in `BUILD-INFO.txt`.

## Changes

- Preserve Ronnie's planners and carry forward strict target validation, v13/legacy parsing, discovery evidence, snapshot/origin bonuses, threat interpretation, settings ownership and shutdown protections.
- Avoid automatic replay of ordinary fleet POSTs at both Go and C# boundaries; retain conservative guards when a result remains uncertain.
- Reserve explicit discovery positions and capacity. Send one bounded position per request, release the dispatch gate between requests for Defender, preserve proven partial outcomes and stop an incomplete cycle.
- Read mailbox summaries before deletion and establish ownership before cleanup, including malformed reports. Preserve manual reports in owned-only mode.
- Recall only fleet IDs confirmed by the specific defensive save, instead of inferring ownership from general movement snapshots.
- Keep upstream proposals compatible with Ronnie's .NET9; our fork uses .NET10. Public version/title/tag: `3.5.1-beta2a`; NuGet: `3.5.1-beta2.a`; numeric assembly/file input: `3.5.1`.

The changes are also proposed to Ronnie upstream. Their merge schedule does not control this fork's releases. Previous maintenance Git history is retained; old 3.4.6a/b release downloads are being retired from the legacy repository.

## Verification and limits

- Clean upstream source: 511/511 .NET9 tests passed in both default and Release configurations; ownership repair covering suite: 64/64.
- Fork .NET10: 513/513 tests passed in a diagnostic full run. One earlier local full build/run had 512 passes and a three-second priority-test timeout. Isolated and full diagnostic runs passed, and a controlled probe verified priority handoff. The original failure is retained; its cause is unproved. No production change or timeout increase concealed it.
- Go: 613 top-level / 840 including-subtests tests passed across 21 test-bearing packages; all packages and the standalone bridge built. Linux and Windows Go CI passed.
- Version policy: 15/15 tests passed. Offline configuration migration: 21/21 passed. Workflow syntax lint passed.

Publication requires native suites and all seven platform builds. ZIPs include checksums, source provenance, public sample settings and the matching backend. Cross-build success does not mean runtime testing on seven operating systems.

No live OGame login, account action or real fleet-send validation was performed. A concurrent indistinguishable manual action cannot be uniquely attributed without server support; this is not universal idempotency. Unconfirmed actions remain guarded in memory; restarting clears those guards and does not prove an earlier action failed. The legacy native discovery route remains compatible and unbounded; this client uses only the new bounded route.

Inherited compiler warnings and dependency advisories remain visible: ImageSharp 3.1.12 and SQLitePCLRaw 2.1.10 need a separate dependency migration. This release does not claim those warnings are resolved.

## Upgrade

Use the bundled backend from this exact release. Keep the previous client directory for rollback, verify `SHA256SUMS` and `BUILD-INFO.txt`, and migrate settings/profiles privately. Add missing public defaults conservatively with new optional features disabled. Stop the old client and its backend before manually starting the prepared new folder.
