# TBot 3.5.1-beta2b

Maintenance prerelease based on Ronnie **v3.5.1-beta2**. Retains the stability changes shipped in **3.5.1-beta2a** and its exact Go backend pin.

Independent upstream proposal: https://github.com/ronnie32/TBot/pull/6.

## Fixed

- Automatic expeditions now share available PrimaryShip counts across the remaining planned sends from each origin, after PrimaryToKeep. For example, 12 LargeCargo and three pending sends from one origin produce 4/4/4 instead of 12/0/0.
- The sharing forecast uses a copy of the existing dispatch planner, respecting active expedition load, origin caps, fair rounds, tie order, exclusions and current slot availability. It adds no game requests.
- Integer remainder allocation avoids starving early fleets when fewer primary ships than pending sends are available. The existing ideal composition remains the upper bound.
- Applying PrimaryToKeep no longer modifies the shared origin ship snapshot.

Available escorts may still be sent with no primary ships. Scarce escorts remain eligible for individual sends. ManualShips composition, confirmed-failure handling and the ambiguous-dispatch stop retain their existing behavior. Already dispatched ships cannot be rebalanced after a later origin failure.

## Validation

- .NET10 full fork suite: 528 passed, 0 failed, 0 skipped.
- Independent .NET9 proposal on Ronnie's unchanged released base: 193 passed, 0 failed, 0 skipped.
- 15 new offline tests exercise real composition calculations and planner forecasts, including reserves, remainder distribution, zero primary, rare escorts, multiple origins, origin caps, slot loss and confirmed rejection. The original 12/0/0 behavior was reproduced before the fix.
- No live account login, real fleet send or running-client API was used during development. Inherited dependency advisories remain; this release does not upgrade dependencies.

Public version/tag: `3.5.1-beta2b`; package version: `3.5.1-beta2.b`. The author base remains a beta, so this release remains a prerelease.
